# Y先生文献の書斎

Y先生が批判的吟味をした論文集です。個人的に行っている非公開版より吟味が甘くなっているかもしれません。クローズドの論文は内容が極めて限定的にしか紹介できないし、オープンの論文でも図などの引用は2－3点以内にしています。

## 現在の公開先・掲載方法

- [公開の文献の書斎](https://y-sensei-study-library.mxe05064.chatgpt.site/)
- [本人専用の掲載・編集画面](https://private-study-library.mxe05064.chatgpt.site/public-manage)

新しい資料の掲載、HTMLの差し替え、タイトル・分類・タグ・紹介文の変更は、本人専用の掲載・編集画面で保存します。GitHubの画面を開いてアップロードしたり、更新依頼を作成したりする操作は不要です。公開の読者はログインせずに閲覧できます。

公開データの正本は新しい公開書斎の保存先です。このリポジトリは、移行時点の原HTML・分類情報・Git履歴と、旧URLから新公開先への案内を保持します。移行後の管理画面での変更が、このGitHubリポジトリに自動追記される構成ではありません。

`publication.json` が存在する場合、`scripts/build.py` は通常どおり原HTML・画像参照を検証してから、**配信用の出力だけ**を新公開先への案内ページに切り替えます。トップ、既存記事と同じファイル名のURL、`manage.html` が対象です。元HTMLとそのメタデータは変更しません。記事内のしおりと、管理画面の既存記事指定は引き継ぎます。JavaScriptを無効にした場合も、新公開先への通常のリンクが表示されます。

以下は移行前のGitHub運用の記録です。現在の掲載・編集には上記の本人専用画面を使用してください。

## 公開用の文献を追加する

1. [掲載者メニュー](https://mxe050.github.io/y-sensei-study-library/manage.html)で「新しく文献を掲載する」を選び、UTF-8で保存したHTMLを指定します。画像を埋め込んだHTMLは、その1ファイルで掲載できます。
2. 「GitHubのアップロード画面を開く」からHTMLを選び、`Commit changes` で保存します。分類とタグは掲載後も入力できます。最初から設定したい場合は、メニューで入力し、ダウンロードした分類・タグのファイルをHTMLと同じフォルダに一緒にアップロードします。
3. 別添え画像やCSSはHTMLとの相対位置を保って一緒に保存します。たとえば `articles/paper-a/index.html` と `articles/paper-a/images/figure1.jpg` を配置します。外部URLの画像は配信元に依存します。
4. [公開処理](https://github.com/mxe050/y-sensei-study-library/actions/workflows/pages.yml)が完了すると件数とリンクが目録に載ります。すでに開いている画面からは最新版の一覧を開けます。

このリポジトリのファイルと履歴は公開されます。コミットする資料は公開用に作成した版を使用してください。

## タイトルを変更する

- **文献のタイトル**　変更したい文献の「タイトル・分類・タグを編集」を開き、「文献タイトル」を変更します。GitHubで保存に進み、所有者として **Create** を押すと、一覧と文献を開いたタブに反映されます。空欄に戻すと原HTMLのタイトルを再び使います。文献のURLは同じです。
- **書斎のタイトル**　[掲載・編集の「書斎のタイトルを変更」](https://mxe050.github.io/y-sensei-study-library/manage.html#site-title-settings)を開き、新しい名前（80文字まで）を入力します。「GitHubで書斎名を保存」から **Create** を押すと、表紙や各ページの書斎名に反映されます。

## 分類とタグを変更する

掲載者メニューで文献を選ぶと現在の分類とタグが表示されます。値を変更し、GitHubでの保存に進みます。所有者アカウントで、入力済みの更新依頼を **Create** で確定すると、GitHubが目録の更新と公開を実行します。処理結果はその依頼で確認できます。分類の空欄は「未分類」、タグの空欄はタグなしとして保存されます。管理画面のファイルを使う方法では、書き込み権限のある共同編集者も変更できます。

分類は文献ごとに1つ、タグは複数設定できます。一覧で分類とタグの両方を指定すると、両方に該当する文献が表示されます。

## 新しいHTMLに差し替える

管理画面で差し替える文献を選びます。表示されたGitHubフォルダに、元と同じ名前のHTMLをアップロードしてコミットします。公開URLと目録のIDを引き継ぎ、本文と一覧の内容が更新されます。別添え画像も同じ位置に置きます。以前の版はGitHubのファイル履歴で確認できます。公開ページには目録への戻りリンクが付きます。スマートフォンの画面幅を指定していない資料には表示幅の設定を補い、大きな画像には画面幅に収まる基本スタイルを加えます。GitHubに保存した元ファイルはそのままです。

## 目録の表示を整える

一覧には管理画面で設定した文献タイトルを使います。未設定の場合はHTMLの `title` を使い、指定がなければ最初の `h1`、続いてファイル名を使います。HTMLの `head` に分類やタグ、紹介文を記入することもできます。掲載者メニューで保存した分類とタグがあればそちらを優先します。

```html
<title>掲載する論文のタイトル</title>
<meta name="study-category" content="臨床疫学">
<meta name="study-tags" content="GRADE, システマティックレビュー">
<meta name="description" content="この論文で検討した問いと、解釈の要点。">
```

一覧に載るのは `articles/` 直下の `.html`・`.htm` と、資料フォルダの `index.html`・`index.htm` です。更新日はHTMLを最後に変更したコミットの日付です。画像や補助ページは同じフォルダ構成で配信します。

## ローカルで確認する

```sh
python3 scripts/build.py --output /tmp/y-study-preview
python3 -m http.server --directory /tmp/y-study-preview 8000
```

`http://localhost:8000/` を開きます。再生成には空の出力先を使います。画像参照がローカルにあるのに実ファイルが見つからない場合はビルドが止まり、ファイル名が表示されます。確認対象は `img` の `src` とSVG `image` の `href` です。

GitHub Pagesの公開元はリポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** です。`main` が更新されるたびに `.github/workflows/pages.yml` が公開用ディレクトリを生成し、文献を含む静的サイトを配信します。
